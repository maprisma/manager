- **P1 — Codex can read and transmit existing private data.** [ask_ai.dart:670](packages/maprisma_manager_core/lib/src/ai/ask_ai.dart#L670) overlays the entire real `.codex` directory, including sessions and configuration; `auth.json` is also bound writable. Codex retains shell tools, and the jail retains network access. A prompt injection in a failed build’s log can ask it to read old conversations or credentials and transmit them. **Fix:** use an isolated Codex configuration containing only required authentication, disable MCP and other inherited integrations, and enforce network restrictions on executable tools.

- **P1 — `pub_get` bypasses job serialization.** [ai_update.dart:315](packages/maprisma_manager_core/lib/src/ai_update.dart#L315) runs it directly rather than through `JobEngine`. While a user or another Manager instance builds, updates, or removes the same app, AI can rewrite its package state concurrently. **Fix:** implement package fetching as a job using the existing queue, cross-process lock, and app-busy checks.

- **P2 — Package discovery does not confine pub’s writes.** [ai_update.dart:362](packages/maprisma_manager_core/lib/src/ai_update.dart#L362) confines the working directory, but runs unrestricted `pub get`. An app package using `resolution: workspace` can resolve through an ancestor workspace and modify package state for sibling projects, including the Manager. Symlinked package output directories provide another escape. **Fix:** validate workspace membership and resolved output paths, or sandbox writes to explicitly permitted app folders and package caches.

- **P2 — Stop cannot terminate a running package fetch.** [ai_update.dart:362](packages/maprisma_manager_core/lib/src/ai_update.dart#L362) awaits `ctx.runner.run`, but cancellation only targets `AskRunner` and `_job`. A stalled fetch continues for five minutes after Stop; `Runner` kills only its immediate process on timeout, so descendants can survive. **Fix:** run package fetching through a cancellable job with process-group termination.

- **P2 — Cancellation during status collection still starts the helper.** [ai_update.dart:239](packages/maprisma_manager_core/lib/src/ai_update.dart#L239) awaits `readApps()` without checking cancellation afterward. Clicking Stop during that await calls `runner.cancel()`, but the subsequent `AskRunner.run()` resets its cancellation flag and starts a fresh request. Data is sent and tokens consumed after cancellation. **Fix:** check `_cancel` immediately after status collection and before invoking `ask`.
